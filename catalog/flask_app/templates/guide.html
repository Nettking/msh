Setup guide

What should I choose during setup?

Use this when the Setup page asks what this computer should do, whether to continue, or whether to start clean.

1

Choose the computer role

Use Web workbench for most analysis and field-review work. Use Full server when this computer should analyze and record data. Use Recorder station for dedicated data capture with setup and diagnostics pages.

Open Setup
2

Choose AI only if it helps

The AI explainer is optional. Ollama can run here or be contributed by a connected computer. Enable it when you want help understanding the repo, data flow, or app pages. It is not required for monitoring, capture, MTConnect tests, or SysML export.

Open Connections
3

Find machines only for recorder roles

If this computer records from MTConnect, use the network scan in Setup's Recorder step and select the stable identities read from the machine data. For workbench-only machine connection tests, use System → Sources instead.

Open recorder setup
4

Continue vs Start clean

Choose Continue when you want to reuse existing runtime/session progress. Choose Start clean when the runtime state looks wrong or you want FCP to rebuild its working state. Existing files stay on disk.

Recommended knowledge flow

From field note to SysML

Do not try to model everything while standing at the machine. Capture first, structure later.

1

Capture a raw statement

Write what the operator said or what you observed. One useful sentence is enough.

Open Capture
2

Review notes later

Go through the captured statements after the visit and decide which ones are useful.

Open Review Notes
3

Structure the note

Map the statement to context, observation, hypothesis, action, rationale, risk, evidence, and outcome.

Open the note inbox
4

Compare strategies

Look for repeated situations, useful actions, trade-offs, and strategies worth reusing.

Open Strategies
5

Add intervention logic

Add telemetry rules only when the situation can be detected from signals such as load, vibration, or state changes.

Open Intervention Logic
6

Export to SysML

Export reusable strategies using the paper method: coded statement → OSL keywords → SysML artefact.

Open SysML Export
Important distinction

Strategy

A strategy is interpreted operator knowledge. It explains a situation, what the operator did, why, what trade-off they accepted, and whether it worked.

Important distinction

Intervention Logic

Intervention logic is technical detection logic. It uses telemetry to find candidate situations where a strategy might be relevant.

Common questions

Where should I go?

I am at the machine and heard something useful.

Go to Knowledge → Capture and write one raw statement. Do not structure it yet.

I want help choosing setup options.

Go to System → Guide → Setup guide. It explains computer role, AI, recorder sources, Continue, and Start clean.

I want to turn notes into strategy fields.

Go to Knowledge → Review Notes, open a note, and fill in the fields you can justify.

I want to add machines, MTConnect URLs, or vibration sensors.

Go to System → Sources. Add the machine first, then add MTConnect URL, VPN/network test target, and any vibration sensors.

I want to test MTConnect or VPN/network reachability.

Go to System → Sources. Use Test MTConnect to check the adapter endpoint and Test VPN/network to check whether FCP can reach the configured machine-network host from the server/container.

I want to know if FCP is ready or why data is missing.

Start with Monitor → Overview. If something looks wrong, use System → Diagnostics.
