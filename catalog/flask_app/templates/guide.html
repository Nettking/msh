Guide

Use this page when you are unsure where to go next. MSH is organised around three areas: Monitor, Knowledge, and System.

The short version

Monitor

Use Monitor when you want to see what is happening now: overview, live data, playback, and support cards.

Open Monitor

Knowledge

Use Knowledge when you want to capture operator experience and turn it into structured strategies.

Start Capture

System

Use System when you need setup, sources, machines, sensors, or diagnostics.

Open Sources

Recommended knowledge flow

1. Capture a raw statement

When you are at the machine or talking to an operator, write one statement in plain text. Do not analyse it yet.

Capture

2. Review notes later

After the visit, go through captured notes and decide what each note means.

Review Notes

3. Structure the note

Map the raw statement into OSL/paper fields such as context, observation, hypothesis, action, rationale, risk, evidence, and outcome.

Open Inbox

4. Compare strategies

Compare structured notes by situation and action. Look for patterns, trade-offs, and reusable knowledge.

Strategies

5. Add intervention logic when detection is possible

Use Intervention Logic only for technical telemetry rules that detect candidate situations. It is not the same as an operator note.

Intervention Logic

6. Export reusable strategies to SysML

Reusable structured notes can be exported using the paper method: coded CNC strategy statement → OSL keywords → SysML artefact.

SysML Export

Common questions

Where do I add machines and sensors?

Use System → Sources. This is where machines and vibration sensors are registered.

Where do I check if the app is ready?

Use Monitor → Overview first. If something is wrong, use System → Diagnostics.

Where is the difference between strategy and intervention logic?

A strategy is interpreted operator knowledge. Intervention logic is a technical rule that detects a candidate situation from telemetry.
